# 0001 · 用 Cloud Run Job + Service，共用一個映像檔

**背景**：系統有兩種工作：每 6 小時跑一輪評測（約 6 分鐘的批次工作），以及隨時回應查詢的 API。流量很小，希望在免費額度內運作。

**決定**：
- 評測用 **Cloud Run Job**，由 **Cloud Scheduler** 每 6 小時觸發
- API 與儀表板用 **Cloud Run Service**，沒有流量時縮到零，最多 1 個執行個體
- 兩者使用**同一個 Docker 映像檔**，只是啟動指令不同

**考慮過的替代方案**：
- **Compute Engine VM**：24 小時計費，還要自己更新系統、修補漏洞
- **GKE**：功能強大，但叢集本身的成本與維運負擔對兩個小服務來說太重
- **在 API 裡開背景執行緒定時評測**：Cloud Run 沒有請求時會縮到零，背景執行緒會被停掉；評測負載也會拖慢 API

**影響**：
- ✅ 成本幾乎為零；評測與查詢互不影響；程式碼只有一份，部署一次兩邊都更新
- ⚠️ 冷啟動：API 閒置後的第一個請求需要數秒。若正式上線需要穩定的回應時間，可設定 `min-instances=1`（代價是持續計費）
