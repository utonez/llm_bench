# 0005 · 不自動重試；依供應商控制呼叫間隔

**背景**：這是一個量測穩定度的平台。如果失敗就自動重試，成功率會被美化，量不到模型真實的穩定度。

**決定**：
- **不自動重試**，失敗如實記錄並分類：`timeout`、`rate_limit`、`auth`、`invalid_request`、`server`、`bad_response`
- Cloud Run Job 也設定 `max_retries = 0`：一輪失敗本身就是數據
- **依供應商控制呼叫間隔**：Gemini 4.5 秒、Groq 2.5 秒，維持在免費額度的每分鐘上限以內

**為什麼需要控制間隔**：第一次在雲端執行時，Gemini 的成功率只有 63%，27 次呼叫中有 10 次被限流。原因是我們的客戶端連續送出請求、超過每分鐘上限，**量到的是我們自己的問題，不是模型的穩定度**。加上間隔後成功率回到 100%。

**同類修正**：推理型模型（gpt-oss）在額度太小時會回傳空白或被截斷的答案。這是我們的設定造成的，因此依模型設定最低輸出額度（`min_output_tokens`），並記錄調整日期。

**影響**：
- ✅ 成功率反映模型與供應商的真實狀況
- ✅ 錯誤有分類，儀表板可以看出問題類型
- ⚠️ 一輪約 6 分鐘（同一供應商依序呼叫）；Job 的逾時上限為 15 分鐘
