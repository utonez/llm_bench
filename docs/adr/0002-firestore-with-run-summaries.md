# 0002 · 用 Firestore，並另存每輪摘要給 API 讀取

**背景**：每輪評測產生 135 筆呼叫紀錄（27 題 × 5 個模型），一天 4 輪。Firestore 免費額度為每天 5 萬次讀取。如果 API 每次都讀取原始紀錄，查一週的統計約需 2,300 次讀取，很快就會用完額度。

**決定**：
- 原始紀錄存在 `bench_results`（每次呼叫一份文件，保留稽核與細查用）
- Job 另外寫入 `run_summaries`：每輪、每個模型一份摘要，**保留成功呼叫的延遲列表**，讓跨多輪計算的 P95 仍然精確
- API 只讀摘要，並快取 5 分鐘

**考慮過的替代方案**：
- **Cloud SQL**：可以直接用 SQL 統計，但沒有免費方案，最小規格每月也要數百元
- **BigQuery**：適合大量分析，但不適合作為 API 背後的即時資料庫
- **只存平均值和 P95**：跨多輪無法正確合併 P95（多個 P95 的平均不等於整體的 P95）

**影響**：
- ✅ 查一週約 84 次讀取；快取讓讀取次數有上限，不受流量影響
- ✅ 文件 ID 由內容雜湊產生，重新寫入不會產生重複資料
- ✅ 程式透過 Repository 介面存取，測試用記憶體版本，未來換資料庫不需改商業邏輯
- ⚠️ 資料量大幅成長時，可將原始紀錄匯出到 BigQuery 做分析
