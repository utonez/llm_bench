# 0007 · 公開 API 採用整體速率限制，不做每位使用者限制

**背景**：查詢 API 公開且不需登入（資料是彙總後的評測結果，不含敏感資訊）。需要防止有人大量請求造成成本增加。

**決定**：
- 每個執行個體每分鐘最多 120 次請求，超過回傳 429
- Cloud Run 最多 1 個執行個體，所以這等於**整個服務的流量上限**
- 加上 5 分鐘快取：不管流量多大，Firestore 的讀取次數都有上限
- 只允許 GET、參數驗證、錯誤訊息不洩漏內部細節

**考慮過的替代方案**：
- **依使用者 IP 限制**：Cloud Run 前面沒有負載平衡器時，無法取得可信的使用者 IP（`X-Forwarded-For` 可以被偽造）
- **負載平衡器 + Cloud Armor**：可以做每個 IP 的限制，但每月有固定費用，對這個專案太重

**影響**：
- ✅ 資料安全、成本有明確上限
- ⚠️ **已知取捨**：只要有一個人大量請求，其他使用者最多會有 60 秒收到 429。這只影響可用性，不影響資料或成本。正式上線時應改用 Cloud Armor
