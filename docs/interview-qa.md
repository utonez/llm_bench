# 面試問答準備

## 專案與動機

**Q：這個專案在做什麼？**
用一組有出處的金融任務，每 6 小時自動測試多個 LLM 的穩定度、延遲、正確率和新台幣成本，幫助企業決定哪個模型適合哪種業務。

**Q：為什麼選這個題目？**
金融業正在導入生成式 AI，選模型時最缺的是「在自己的任務上、實際的表現與成本」。而且這個系統的數據要長期累積，必須放在雲端定期執行，剛好能展現雲端架構的設計。

**Q：數據是真的嗎？**
是。每一次呼叫都是真實的 API 呼叫，延遲是實際量測；題目來自公開資料集和金管會、央行的新聞稿，每題都可以追溯出處。成本使用 OpenRouter 的公開市場價格，因為實際呼叫用的是免費額度。

## 架構

**Q：請說明架構。**
Cloud Scheduler 每 6 小時觸發 Cloud Run Job 執行評測，金鑰從 Secret Manager 取得，結果寫入 Firestore。Cloud Run Service 提供查詢 API 和儀表板。全部用 Terraform 建立，部署在台灣的 asia-east1。

**Q：為什麼用 Cloud Run，不用 VM 或 Kubernetes？**
流量很小、評測是批次工作。Cloud Run 沒有流量時縮到零，幾乎不花錢，也不用管作業系統。Kubernetes 對兩個小服務來說維運成本太高。

**Q：為什麼評測用 Job，不在 API 裡定時跑？**
Cloud Run 沒有請求時會縮到零，背景程式會被停掉；而且把批次工作和 API 分開，評測負載不會拖慢查詢。

**Q：Firestore 免費額度夠嗎？**
如果 API 直接讀每一次呼叫的紀錄，查一週要約 2,300 次讀取。所以 Job 另外寫入每輪摘要，查一週只要約 84 次，再加上 5 分鐘快取，讀取次數有上限。

**Q：P95 跨多輪怎麼算？**
不能把每輪的 P95 平均，數學上不正確。所以每輪摘要保留了所有成功呼叫的延遲數值，合併後再算整體的 P95。

## 安全

**Q：API 金鑰怎麼管理？**
只放在 Secret Manager，不在程式碼、映像檔或 Terraform 的狀態檔裡。Terraform 只建立空的 secret，值由人用 gcloud 寫入。只有評測 Job 的服務帳號能讀。

**Q：CI/CD 怎麼登入 GCP？**
用 Workload Identity Federation：GitHub 簽發 OIDC token，GCP 換發約 1 小時有效的臨時憑證，GitHub 上沒有存放任何金鑰。GCP 端限定只接受這個 repo 的 main 分支，所以 PR 拿不到部署憑證。

**Q：公開的 API 怎麼防止被濫用？**
只允許 GET、參數有範圍驗證、速率限制、5 分鐘快取、最多 1 個執行個體。所以就算被大量請求，成本和資料庫讀取都有上限。已知的取捨是速率限制是整體共用的，見 ADR 0007。

**Q：做了哪些供應鏈安全措施？**
Python 套件用雜湊鎖定，被竄改就無法建置；基底映像檔固定 digest；GitHub Actions 固定 commit SHA；Chart.js 驗證過 npm 的完整性雜湊才放進專案。

## 開發過程

**Q：遇過什麼困難？**
第一次在雲端執行時，Gemini 成功率只有 63%。查錯誤類型發現全是限流，原因是我們送得太快、超過每分鐘上限。這是我們的問題，不是模型的問題，所以加上呼叫間隔，成功率回到 100%。這讓我學到：數據要交叉檢查才能相信。

**Q：為什麼不自動重試失敗的呼叫？**
這是量測穩定度的平台。自動重試會把失敗藏起來，成功率就不準了。

**Q：AI 在這個專案扮演什麼角色？**
我是專案的發想人，負責提出想法和方向，例如要求題庫必須有出處、決定增加受測模型；AI 負責執行。但 AI 還沒有到不需要人工審核的程度，所以 Claude Code 寫完程式碼後，我會再檢查一次內容才合併。過程中 AI 也犯過錯，例如一開始編造題目、測試失敗的版本被部署，所以我加上了 CI 和分支保護，讓流程能自動抓到錯誤。詳見 [AI 輔助開發](ai-assisted-development.md)。

## 結果與延伸

**Q：測出什麼結論？**
速度和正確率有取捨：Gemini 最準，但延遲長尾明顯；Groq 的模型穩定在 1 秒左右。新一代模型比較穩定；模型越大不一定越準；推理型模型有隱藏的 token 成本。

**Q：如果要正式上線，還要做什麼？**
- API 加上身分驗證，或改用 Cloud Armor 做每個 IP 的速率限制
- 監控與告警：成功率下降時通知
- 題庫擴充，並加入人工評分或 LLM 評分來評估摘要品質
- 原始資料匯出到 BigQuery 做長期分析
- 依業務需求設定 `min-instances` 避免冷啟動
